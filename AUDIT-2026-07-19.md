# DebtPayoffCalculator — Audit Report, 2026-07-19

## 1. Executive summary

The app is in good shape where it matters most: the monthly simulation engine (interest accrual, avalanche/snowball ordering, minimum rollover, savings drawdown, breakdown detection, the 600-month cap) was verified against independent reference math and closed-form amortization and is **correct to the cent**, including zero-APR, min-greater-than-balance, promo rate changes, and card-charge routing. The serious problems were all around the edges: a corrupt or hostile import could permanently poison the saved `dfc6` state, the df5 migration silently turned an explicit 0% tax into 22% and silently dropped expenses linked to unknown accounts from the math, the "Sample" button destroyed real data with no confirmation, month arithmetic skipped a month when the app was opened on the 29th–31st, and the "offline" app hard-depends on a CDN copy of Chart.js that takes the Projection and Consolidate tabs down with it. All of those are fixed in `index.html` and verified by a new automated test suite (`tests/`, 20/20 passing) plus a full-page headless smoke test in both online and CDN-blocked conditions. Remaining gaps (integer-cents arithmetic, vendoring Chart.js, consolidation-vs-charges modeling, feature ideas) are itemized below with sketches.

Baseline before fixes: **16/20 tests passing**. After fixes: **20/20**, zero console errors in full-page smoke, sample scenario's 30-yr mortgage independently confirms real-world amortization (payoff month 361).

## 2. Findings (Critical → Low)

Line numbers refer to the post-fix `index.html` unless marked *(pre-fix)*.

### Critical

- **C1 — FIXED. Import could permanently corrupt saved data.** *(pre-fix `importJSON`/`normalize`)* `importJSON` assigned the parsed file straight into the live `S` before validating; `normalize()` would throw on e.g. `debts: "garbage"`, leaving `S` corrupted in memory. The next keystroke's `save()` then wrote the corrupt object to `localStorage['dfc6']`; on every later launch `load()`'s catch silently discarded it for a blank default — the user's data was gone. Fix: `normalize()` (index.html:1679) is now a never-throws repair pass (type/array coercion, numeric clamping, enum whitelists), and `importJSON` (index.html:1769) keeps the previous state and restores it on any failure or on declined confirmation. Verified by tests T14/T15/T20.

- **C2 — FIXED. "Sample" button wiped real data with no confirmation.** *(pre-fix `loadSample`)* One click replaced all debts/expenses/income and saved immediately; no undo exists. Now asks for confirmation whenever non-sample user data is present (index.html:1819). Import similarly confirms before replacing existing data.

### High

- **H1 — FIXED. df5 migration lost an explicit 0% tax rate.** `n.taxPct = o.tax || 22` turned a stored `tax: 0` into 22%, silently misstating take-home income after migration. Now preserved (index.html:1743). Test T12.

- **H2 — FIXED. Expenses tied to a deleted/unknown account silently vanished from the math.** An expense whose `paidWith` pointed at a nonexistent debt id (possible via import or df5 migration; the in-app delete path remaps to cash but nothing else did) was excluded from cash expenses *and* never charged to any card — the projection quietly overstated the monthly budget while the UI showed only a small "card deleted" badge. `normalize()` now reroutes orphaned `paidWith` to `cash` (index.html:1712-1717). Test T15.

- **H3 — FIXED. Offline use killed two tabs.** Chart.js loads from cdnjs (index.html:7); with no network, `new Chart(...)` threw and aborted `renderProjection`/`renderConsolidate` mid-render — dead panels on an app whose footer promises local, offline operation. Now degrades gracefully: a message replaces the canvas and the timeline/tables/numbers keep working (chartFallback, index.html:587; guards at 1122 and 1477). Verified by CDN-blocked smoke run. True fix is vendoring the library — see Deferred D2.

- **H4 — FIXED. Month arithmetic skipped months at month-end.** `dateFromMonth` used `setMonth` on today's date; opened on Jan 29–31, "+1 month" clamps to Mar 2–3, so February disappeared from chart labels, payoff dates, and rate-change effective dates (a promo expiry could shift a month). Now normalized to the 1st of the target month (index.html:570).

- **H5 — FIXED. Hostile/garbage numeric fields propagated into the engine and the DOM.** Imported JSON with `apr: "<img onerror=...>"`, string balances, negative amounts, or `1e308` values flowed unescaped into `innerHTML` fragments (`d.apr` and `d.color` are interpolated raw in `renderDebts`/`renderTimeline`) and into the simulator (Infinity balances would reach Chart.js). `normalize()` now coerces every numeric field, clamps to `[0, 1e12]` (APR to 999), and whitelists colors against `/^#[0-9a-fA-F]{3,8}$/`; `simulate()` additionally breaks on non-finite totals (index.html:672). Tests T15/T19/T20.

### Medium

- **M1 — FIXED. One-tap debt deletion with no undo.** The ✕ button removed a debt instantly. Now confirms with name and balance (index.html:1606). Expense deletion is still one-tap (see L5).

- **M2 — FIXED. Typing decimals in "Extra Monthly Payment" was broken.** Every keystroke triggered `refresh()` → `renderDebts` rewrote the focused input, so "250." lost its dot mid-entry and a leading "0" emptied the field. The field is no longer rewritten while focused (index.html:927).

- **M3 — FIXED. Silent save failures.** `save()` swallowed quota/blocked errors; the user could edit for an hour and lose everything. Now shows a one-time warning toast suggesting Export (index.html:1661).

- **M4 — FIXED. Consolidation mislabeled term-cap failures as "Payment Too Low".** With a term cap, a payment that covers interest but doesn't finish within the term got the same label as a payment below interest. Now distinguishes "Needs Longer Term" / "Not within term" (index.html:1509, 1517).

- **M5 — FIXED (performance). `aprAt` re-sorted and re-parsed dates constantly.** It ran `slice().sort()` plus `new Date()` parses per debt per month *and inside the avalanche sort comparator* — thousands of allocations per simulation, multiplied by the Advisor's extra simulations and every slider tick. Rate-change timestamps are now precomputed once per simulation and the month timestamp once per iteration (index.html:653-665). Not user-visible before, but it removes the main scaling hazard alongside chart rebuilds.

- **M6 — OPEN (model honesty). Consolidation comparison flatters consolidation when expenses are card-routed.** `simConsolidated` starts from `totalDebt` only; the current-plan number it's compared against includes interest on *future* card charges from routed expenses. After consolidating, those charges would still exist (paid in cash, or worse, re-charged). The comparison is apples-to-oranges by the amount of charge-driven interest. See Deferred D3.

- **M7 — OPEN (model honesty). "Cost per $1" denominator ignores future charges.** `trueCost = 1 + totalInterest/totalDebt` divides interest that includes charge-driven balances by the *initial* debt only, overstating cost-per-dollar when expenses are routed to cards. Cosmetic-to-minor; worth a footnote in the UI or a denominator that adds cumulative charges.

- **M8 — OPEN. Migration drops df5 features rather than data.** Old fields `projYears`, `incomeGrowthRate`, `studentLoanPlan`, `pslfYearsIn`, `hasMortgageDeduction`, `marginalTaxRate`, `checkingRate`, and the `retroactive` flag on APR changes have no dfc6 equivalent (the features were removed in the rewrite). Nothing user-entered that the new app *can* represent is lost, and the df5 key is left intact in localStorage (good — re-migration stays possible), but this should stay documented. If income growth ever returns, the migration should be revisited before the df5 key is retired.

### Low

- **L1 — Float money, not integer cents.** Balances/payments are IEEE doubles. Tests show totals match reference math within $0.01 over 600 months and payoff thresholds (0.005) absorb residue, so there is no visible drift today; display rounds to whole dollars. Still, cents-integer arithmetic is the principled fix — see Deferred D1.

- **L2 — Independently rounded display rows can disagree by $1.** `money()` rounds each figure separately, so "Where It Goes" rows may not sum exactly to the total shown. Cosmetic.

- **L3 — Timeline rate-change dates use a different month calculation than the engine.** `renderTimeline` divides by 30.44-day months while the sim uses calendar months; the marker can sit one month off from when the sim actually applies the rate. Cosmetic.

- **L4 — Extra-payment slider hard-capped at $2,000/mo.** A larger typed value works but the slider clamps its display. Could scale `max` to the available budget.

- **L5 — Expense deletion has no confirm/undo.** Left as-is (3 fields to re-enter); listed for completeness.

- **L6 — Gross-mode tax model applies the full tax % after the 401(k) deduction.** Traditional 401(k) is income-tax-exempt but not FICA-exempt, so net is slightly overestimated for gross-mode users with 401(k). It's an explicitly labeled estimate; acceptable.

- **L7 — `efMonths` input silently coerces 0/blank to 3** while the field still shows what was typed. Trivial.

### Verified-good (worth recording)

- Engine math vs closed-form/reference amortization: exact (T1–T3, T10, T16).
- Strategy ordering, rollover ("debt snowball" mechanics), mortgage exclusion toggle: correct (T4, T5, T18).
- Savings drawdown and plan-breakdown month: exact (T6, T7).
- Pathological input guard: `MAX_MONTHS = 600` cap terminates giant-balance sims in milliseconds (T8).
- No negative balances ever appear in snapshots (T9).
- df5→dfc6 migration field mapping incl. paycheck-stub mode and `payAccount`→`paidWith`: correct (T11, T13); df5 key is preserved after migration, so migration is retryable.
- XSS: user-entered names are consistently escaped via `esc()`; the import-borne vectors (apr/color) are closed by H5.
- Real-world sanity: sample 30-yr mortgage amortizes to exactly 361 months in the full app.

## 4. Deferred (with design sketches)

- **D1 — Integer-cents money engine (Low urgency).** Convert `balance/minPay/amount/interest` to integer cents at the storage boundary (`normalize()` becomes the single conversion point; schema bump `dfc7` with lossless ×100 migration of `dfc6` *and* keep the df5 path). Inside `simulate()`, round interest to a cent per debt per month (`Math.round(bal * r)`), making payoff tests exact `=== 0` instead of `< 0.005`. Risk: touches every arithmetic line; benefits are mostly theoretical given T1-verified accuracy — do it only alongside another engine change. ~2–3 h with tests.

- **D2 — Vendor Chart.js into the file (true offline).** Inline `chart.umd.min.js` (~200 KB) into a `<script>` block, or replace with a ~150-line hand-rolled SVG line/stacked-area renderer (the app uses a small Chart.js subset: line, stacked area, bar+line combo, two y-axes). Vendoring is 15 minutes once the file is fetched (not done in this session: no downloads without approval); hand-rolled is ~3–4 h but drops the dependency entirely.

- **D3 — Consolidation vs. card-charge honesty (M6).** In `renderConsolidate`, compute the current plan's charge-attributable interest (run `simulate()` once with charges routed and once with all expenses as cash; the delta is charge interest) and either (a) add a caveat line "your card spending adds ~$X of the difference", or (b) model the consolidated scenario with the same charges paid in cash, reducing the payment budget. (b) is more honest; ~1–2 h.

- **D4 — Month labels vs. engine for rate-change timeline (L3).** Replace the 30.44-day division with the same calendar-month walk the engine uses (compare against `dateFromMonth(m)` boundaries). ~15 min.

- **D5 — Undo/soft-delete instead of confirms.** Replace the new `confirm()`s with a toast holding an Undo button and a 10-second grace (keep last-deleted item in memory). Nicer UX, ~1 h.

## 5. Top 5 recommended next investments

1. **Vendor Chart.js (D2)** — the one remaining "offline app that isn't" gap; smallest effort, biggest robustness win. (~0.5 h once the file is approved for download)
2. **Payoff-schedule export** — a per-month table (date, per-debt payment/interest/balance) with Copy-as-CSV and print stylesheet. Users take this to spouses/lenders. Engine already produces snapshots; it's a render + CSV join. (~2 h)
3. **Scenario A/B compare** — "Plan A vs Plan B" (different extra, strategy, or a consolidated loan) side-by-side: two `simulate()` calls, one chart with paired lines, delta cards (months sooner, interest saved). The engine's `opts` parameter was clearly built for this. (~3–4 h)
4. **Consolidation charge-honesty (D3)** — the only remaining place the math can mislead. (~1–2 h)
5. **PWA-ify** — manifest + tiny service worker caching the single file; installable on his phone/tablet, guaranteed offline. Pairs with #1. (~1–2 h)
